# Yazhnova — editorial engineering

This plan follows the completed 16-item source study in [inventory.md](inventory.md) and [shots](shots/). The current brief authorizes building after the plan; it supersedes the earlier approval pause. All 16 sources rendered in the browser. Type-only repairs and the explicitly requested optional stone-intro controls are listed in [fixes.md](fixes.md); no visual recreation is used.

## System

- **Palette:** ink `#0A0A0A`, graphite `#141414`, paper `#F4F2EC`, warm grey `#8C8A84`, hairline `rgba(244,242,236,0.12)`. Signal amber `#FFB45A` comes directly from shadow-cast. Reserve it for small signals, an object surface and small lit areas; it occupies less than 5% of the overall composition. No neon blue/violet, gradient text, glow chips or stock bento.
- **Type:** Instrument Serif regular/italic for expressive display moments; Inter Tight for engineered headings and UI; Geist Mono for section numbers, indices, labels and readouts. Fonts are self-hosted. Titles deliberately contrast with small, readable supporting copy.
- **Grid:** 12 columns in a 1280px content width; 24–80px gutters; real imported hero-28 GridRails/GridFrame components, visible hairlines, edge ticks and section indices. Straight edges, purposeful alignment and generous empty space replace rounded glass cards.
- **Motion:** at most one prominent 3D object per screen. Dither and connecting lines are texture rather than competing hero objects. Canvas sources dynamically import with `ssr:false`; an IntersectionObserver unmounts them off-screen, invoking their original cleanup. Hidden tabs pause them. Reduced motion and small/coarse-pointer screens receive actual source-captured PNGs. No replacement shader, geometry or homemade canvas.
- **Truthful content:** concept projects and unapproved testimonials are clearly identified. No invented client logos, performance statistics or named endorsements. Agent actions are an illustrative workflow, not a connected production integration.

## Deliberate changes to the suggested mapping

The hero-51 eyes are preserved and shown in the playground, but its **layout** is the production contribution. Eye tracking is its original product story and would make Yazhnova look like an unrelated playful product. The source hands and dither better express software made with care.

features-02 is a globe-and-metrics section rather than a service-card component. Its column rhythm and divider hierarchy are useful; the default metrics and worldwide-team claims are not reused.

The footer's real LightShaftText is recolored and slowed. Its default starfield CTA and cyan SDK demo are not needed in the composed footer. Pricing's useful structure is separated from its default cosmic/neon treatment.

Several raw components impose 1200×800 minimum dimensions for their original canvas editor. Adapters override these through the existing `style` prop (`minWidth:0`, `minHeight:0`) so the same real code fits responsive windows. This is sizing, not a visual replacement.
